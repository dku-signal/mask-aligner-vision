# 인계 자료: 웨이퍼 이송 · 프리얼라인 자동화 (2026-11-20)

이 문서는 FOUP(박스)에서 웨이퍼를 꺼내 정밀 얼라인 스테이지에 올려놓는 **이송·프리얼라인 자동화**의 현재 상태를 정리한 것입니다. 다음 사람이 이 문서만 보고 장비를 켜서 수동 조작, 자동 시퀀스, 원상 복구를 돌릴 수 있도록 썼습니다.

## 다음 세션에서 이어갈 지점 · 2026-11-20 오후

**다음 실험은 최종 수치로 실행하는 8→9단계 이송 중 θ 보정이다.** 기존 이송 시퀀스와 정밀 얼라인은 실장비에서 각각 실행했다. 최종 스크린샷 수치와 양방향 550ms를 함께 적용한 뒤에는 패널의 15개 행과 모의 보드 전송 순서를 대조했고, 테스트 52개가 통과했다. 이번 인계 시점에 실장비 동작은 대기 중이다.

### 작업 위치와 실행 상태

- 아래 명령은 저장소 루트에서 실행한다.
- 펌웨어는 `main`의 `firmware/mega_previous`다. 프리얼라인의 실장비 YOLO 가중치는 `runs/keys_real/weights/best.pt`에 있다. 코드만 다시 검증하는 명령은 `python -m pytest -q`다.
- 정밀 패널(8765)은 `GET /api/status`에서 현재 장비 연결과 동작 상태를 확인한다. 이송 패널(8790)은 `GET /status`, `GET /seq`, `GET /cameras`에서 확인한다.

### 최종 동작과 검증 범위

- **고정 수치**는 4장의 0~14단계 표와 `config/prealign_sequence.json`을 따른다. 6단계는 없고 9.5단계가 있다. 1단계 Q는 250,000스텝, 9단계 W는 250,000스텝, 2·10단계 E와 8·14단계 R은 90,000스텝, 11단계 L은 2,700ms, 나머지 L/K는 6,500ms다. 정밀 X의 `F 3200`은 9단계 W 완료 후 한 번만 보낸다. 장부에 기록된 위치로 이 명령량을 줄이지 않는다.
- **프리얼라인**은 8단계 `R 90000` 완료 후 정지 상태에서 카메라 0의 마스크 사각점 8개와 카메라 1의 웨이퍼 십자 2개를 YOLO로 검출한다. 9단계에서 X 전진과 동시에 D8을 한 번 구동한다. 시간은 양방향 모두 `550ms × |각도 차이| / 90°`로 계산한다. ±1.5° 이내면 X만 이송한다. 보드가 D8과 첫 W 구간의 완료를 보고하면 남은 W를 즉시 전송한다. 이전 실측값 574/543ms는 진단 기록이다.
- **정밀 얼라인**은 카메라 0의 `yolo-2pair`로 실행했다. 15:36:39에 8프레임 연속 완료 기준을 통과했고, 정밀 Z 상승 출력 5초에 대해 보드가 `DONE u 5000`으로 응답했다. Z에는 위치 피드백이 없어 실제 상승 높이는 확인이 남았다. 당시 코드에서는 완료 시점부터 10초 뒤 정밀 X·Y가 저장한 오른쪽 위로 복귀했고, `out/fine_stage.json`에 X=0, Y=0, 대기 명령 없음으로 기록됐다. 현재 자동 복귀 순서는 4.2절을 따른다.
- **재시험 조건**을 구분한다. 당시 실장비 재시험은 판이 이미 내려가 있어 임시로 `ALIGN_Z_DOWN_MS=0`을 사용했다. 일반 실행 코드의 정밀 Z 하강·상승 기본값은 각각 5,000ms다. 해당 시험 당시 이송 장부의 X는 272,000스텝이었으며 실제 위치를 읽는 센서는 없다. 전체 실행의 1단계는 어느 위치에서 시작해도 Q 250,000스텝을 보내므로 정밀 스테이지 쪽 출발점을 현장에서 확인한다. 8→9단계만 시험할 때는 7단계까지 웨이퍼를 수취하고 전자석이 켜져 있어야 한다. 포트를 다시 열면 Mega가 리셋될 수 있으므로 보드 점유를 넘길 때는 웨이퍼 지지 상태를 먼저 확인한다.

## 2. 장비 구성과 핀

펌웨어: `firmware/mega_previous/mega_previous.ino` (하드웨어 팀 `MEGA_PREVIOUS.ino` 기반, 자세한 명령은 같은 폴더 README).

## 3. 실행 방법

```bash
pip install -r requirements.txt
python tools/motor_panel.py              # 아두이노 자동 선택, 카메라 0 1 2
python tools/motor_panel.py --mock       # 보드 없이 화면·시퀀스 시험 (가상 보드가 DONE을 20배 빠르게 돌려줌)
python tools/motor_panel.py --cameras    # 카메라 없이
```

브라우저 `http://127.0.0.1:8790`. macOS는 **터미널에 카메라 권한**이 있어야 카메라가 열립니다(시스템 설정 → 개인정보 보호 및 보안 → 카메라).

**켜는 순서 (안전)**
1. SMPS(모터 전원)를 끈 채 USB 연결 → 패널 실행 → "연결됨" 확인 (연결하면 Mega가 리셋됨)
2. SMPS 켜기 → 서보가 돌지 않는지 확인
3. 처음이면 장비를 시작 자세에 두고 **"지금 위치를 기준(0)으로"**
4. 정지: 빨간 버튼 / Space / Esc (진행 중인 줄 명령과 시퀀스 모두 멈춤)

> 웨이퍼를 전자석에 붙이고 있는 동안 패널을 재시작하면 보드가 리셋되어 전자석이 꺼지고 **웨이퍼가 떨어집니다.** 재시작은 웨이퍼를 내려놓은 뒤에.

## 4. 자동 시퀀스 (화이트보드 14단계)

정의: `config/prealign_sequence.json`. 실행: `tools/prealign_sequence.py`. 각 명령을 보드에 `#<글자> <값>`으로 보내고 `DONE`을 받은 뒤 다음 명령으로 넘어갑니다. 전체 약 2분 30초.

| 단계 | 동작 | 명령 | 값의 근거 |
|---|---|---|---|
| 0 | Y 리니어 후퇴, Z 하강, 전자석 OFF | K 6500, O 5000, M 0 | 지정 시퀀스 |
| 1 | X 레일을 FOUP 쪽으로 이송 | Q 250000 | 고정 스텝 |
| 2 | Y 레일 넣기 | E 90,000 | 지정 스텝 |
| 3 | Y 리니어 넣기 | L 6500 | 지정 시퀀스 |
| 4 | 전자석 ON | M 1 | |
| 5 | Z 올려 웨이퍼 잡기 | **P 1100** | 화이트보드 (11/18: 붙는 높이 900 + 여유 200) |
| 7 | Y 리니어 빼기 | K 6500 | |
| 8 | Y 레일 후퇴 완료 후 정지 상태에서 각도 측정 | R 90,000, 두 카메라 YOLO 측정 | 마스크 사각점 8개, 웨이퍼 십자 2개 |
| 9 | X 전진과 θ 보정 후 정밀 X 이동 | W 250000, F 3200 | θ를 보정하면 W 두 구간의 합계가 250,000스텝 |
| 9.5 | Z 올리기 | **P 5000** | 화이트보드 |
| 10 | Y 레일 넣기 | E 90,000 | 지정 스텝 |
| 11 | Y 리니어 넣기 | L 2700 | 지정 시간 2.7초 |
| 12 | Z 내려 전달 | **O 3000** | 화이트보드 |
| 13 | 전자석 OFF | M 0 | |
| 14 | 빼기 | R 90000, K 6500 | |

1·9단계는 현재 장부 위치에 관계없이 지정한 스텝을 보냅니다. 1단계 시작 위치는 긴 X 레일의 정밀 스테이지 쪽 끝입니다.

8단계에서 두 카메라로 보정 전 각도를 측정한다. 마스크 사각점 8개가 YOLO로 잡히지 않으면 정밀 얼라인의 두 격자 검출기로 현재 영상의 명암과 배치를 확인한다. 최소 6점(한쪽 4점, 반대쪽 최소 2점)으로 두 중심을 구하며 패널에는 실측 점 수를 표시한다. 웨이퍼는 원본에서 실패하면 영상의 대비를 늘린다. 같은 프레임을 서로 다른 각도로 돌려 십자 두 개의 위치가 일치하는지 확인한 뒤 각 중심을 보정한다.

### 4.1 위치 기준
- 박스 위치와 여유값은 별도의 **원상 복구**에서 사용합니다.
- 정밀 X·Y를 장비의 오른쪽 위 끝에 놓고 **현재 정밀 X·Y를 오른쪽 위 기준으로 저장**을 누릅니다. 정밀 스테이지의 기준과 누적 스텝은 `out/fine_stage.json`에 저장됩니다.
- 기준은 `out/position_ledger.json`에 저장되고 패널을 재시작해도 유지됩니다.
- 긴 이송 레일은 보관함 끝에서 **지금 X 레일 = 박스 끝으로 기억**을 누릅니다.

### 4.2 정밀 얼라인 완료와 자동 복귀
정밀 X·Y 중심 오차가 각각 0.65px 미만으로 8프레임 연속 확인되면 FINISH다. 9단계 수취 이동은 F 3,200스텝입니다. 정밀 앱은 START 시점의 X·Y 장부 좌표를 기록합니다. FINISH 후 Z 상승이 완료되고 FINISH 시점부터 10초가 지나면 이번 정렬에서 보드가 완료를 확인한 세타 펄스를 역순으로 같은 시간 동안 반대 방향으로 구동합니다. 각도 피드백 없이 구동 시간을 기준으로 복귀합니다. 이어서 X는 START 위치보다 왼쪽(B) 32,000스텝, Y는 START 위치로 복귀합니다. 수동 초기화 버튼의 목적지는 저장된 오른쪽 위입니다. STOP은 대기 또는 복귀를 취소합니다.

## 5. 원상 복구

얼라인이 끝난 뒤 "↩ 원상 복구"를 누르면 장부대로 되돌립니다.

1. Y 리니어 끝까지 빼기 (K)
2. Y 레일 처음 위치로
3. **프리얼라인 서보: 돈 만큼 반대로** (`#t`)
4. **정밀 θ 서보: 돈 만큼 반대로** (`#A`)
5. 정밀 X·Y를 저장한 오른쪽 위 기준으로 복귀
6. X 레일 박스 위치로 (박스 끝 + 8,000)
7. Z 맨 아래

**장부에 기록되는 것:** 자동 시퀀스, "정확한 이동", "회전" 버튼으로 움직인 것. 보드가 `DONE <축> <값>`을 보내면 그 값을, **중간에 정지하면 `STOP <축> <실제로 간 양>`**을 보내서 그만큼 기록합니다(11/20 추가, 실장비 확인). 누르는 동안 움직이는 **수동 버튼은 기록되지 않습니다** — 수동으로 움직였으면 기준을 다시 잡으세요.
**정밀 얼라인 앱이 θ를 돌린 양도 장부에 들어와야** 원상 복구가 정확합니다. 현재 `mask_aligner_optimized_v4.py`는 `aligner_mega` 프로토콜을 쓰므로, 이 펌웨어의 `#A <ms> <±1>`과 `#F/#B/#f/#b <스텝>`을 쓰도록 연결하는 작업이 남아 있습니다.

## 7. 남은 문제와 다음 할 일 (우선순위 순)

0. **장부 기준 다시 잡기.** 11/20 마지막 시험에서 1단계(Q)가 버튼 조작으로 중간 정지되었고, 그 시점엔 `STOP` 이동량 보고 기능이 없었습니다. 다음에 켜면 X 레일을 박스 끝까지 밀고 "지금 X 레일 = 박스 끝으로 기억"을 누르세요.
1. **레일 mm 환산 — 가장 중요.** 지금은 실측 스텝 수입니다. 모터 정보(X 긴 레일, Y·정밀 X·Y = LM-2015R 200mm)의 **리드(mm/회전)**와 **TB6560 DIP 마이크로스텝**을 모릅니다(판매처 데이터시트 PDF가 열리지 않음). 축마다 `#W 20000`처럼 보내고 자로 이동 거리를 재면 스텝/mm가 나옵니다. 그 값으로 `axes`를 mm 기반(스트로크 − 양끝 여유)으로 바꾸세요.
2. **리밋 스위치.** 레일 양끝에 달면 펌웨어에서 끝을 감지해 멈출 수 있고 기준 잡기가 자동이 됩니다.
3. **프리얼라인 실장비 이송 시험.** 7단계까지 수취를 마친 뒤 **8→9단계 1회 시험**을 실행합니다. 8단계 측정 오차가 ±1.5° 이내면 X만 이송합니다. 그 밖에는 양방향 공통 90° 기준 시간(550ms)에 `|각도 차이| / 90°`를 곱해 D8을 한 번 구동합니다. 보드의 첫 W·D8 완료 응답을 받으면 남은 W를 보낸 뒤 F 3200을 실행합니다. 회전 후 각도는 다시 측정하지 않습니다.
4. **정밀 얼라인 앱 연동.** 위 5장 참고. 정밀 X/Y/θ를 이 펌웨어 명령으로 보내야 장부와 원상 복구가 맞습니다.
5. **카메라 3대.** 카메라가 320×240 미만·MJPG 요청을 무시하므로 한 허브에서는 2대까지만 됩니다. 1대를 Mac 본체의 다른 포트에.
6. **레이저 센서 `ADS_ERROR`.** ADS1115 외부 5V·GND 공통·SDA 20/SCL 21 확인.
7. **Y 리니어 튀어나옴.** 끝에 닿은 뒤 살짝 되밀리는 현상(11/18). 기구 확인.
8. 정밀 스테이지 Y 방향(f/b) 미확인.

## 10. 전체 구조

```
브라우저 (http://127.0.0.1:8790, tools/motor_panel.html)
   │  버튼·입력 → HTTP POST, 0.3~0.5초마다 상태 GET
   ▼
tools/motor_panel.py  (파이썬 HTTP 서버, 스레드)
   ├─ Board      : 시리얼 9600bps, 한 글자 명령 / '#' 줄 명령, 응답 큐, 감시견
   ├─ Ledger     : 축 위치(스텝)·서보 누적 회전(ms) 장부 → out/position_ledger.json
   ├─ Cameras    : 카메라 0·1·2를 백그라운드로 읽어 JPEG 제공 (관찰용)
   └─ Sequence   : tools/prealign_sequence.py (자동 시퀀스·원상 복구, config/prealign_sequence.json)
   ▼  USB 시리얼
Arduino Mega 2560 (firmware/mega_previous)
   ├─ Timer2 인터럽트: 레일 STEP 펄스 (50µs 토글), 남은 스텝을 세어 0이면 스스로 정지 → "DONE"
   ├─ DC 축(Z, Y 리니어, 기존 Z): H브리지 IN1/IN2, 시간이 다 되면 정지 → "DONE"
   ├─ 서보 2개(연속회전): 90=정지, 90±30=회전, 시간이 다 되면 90 → "DONE"
   └─ 전자석 D11, ADS1115 레이저(0.2초마다 mm 또는 ADS_ERROR 출력)
```

### 10.1 시리얼 프로토콜 예시

```
PC → #PING            보드 → PONG
PC → #W 10000         보드 → (1초 뒤) DONE W 10000
PC → #P 300           보드 → (0.3초 뒤) DONE P 300
PC → #M 1             보드 → DONE M 1
PC → #t 1716 -1       보드 → (1.7초 뒤) DONE t 1716        (프리얼라인 서보 시계 반대 방향 가정)
PC → #A 400 1         보드 → (0.4초 뒤) DONE A 400         (정밀 θ 서보)
PC → X                보드 → STOP F 9972  (F 20000 중 1초 만에 정지: 실제로 간 양)
                            STOP        (진행 중인 줄 명령이 있었을 때)
PC → F                (DONE 없음) 누르는 동안 이동, X로 정지 — 수동 조작
```

- 줄 명령은 `#`로 시작해야 합니다. `#` 없이 보낸 글자는 한 글자 명령으로 바로 실행되므로, 숫자가 섞인 문자열을 그냥 보내면 안 됩니다(예: `Q 1000`을 `#` 없이 보내면 `Q`가 무한 이동으로 실행됨).
- 레일 이동 중에 서보 회전(`#t`, `#A`)을 같이 보낼 수 있습니다(프리얼라인: X 이송 중 회전). 레일 4개는 펄스 발생기를 공유해 **레일끼리는 동시에 못 움직입니다**(J/H 1+2 동시 제외).
- 범위: 레일 1~2,000,000스텝, DC 1~30,000ms, 서보 1~20,000ms. 벗어나면 `ERR`.

### 10.2 패널 HTTP API (자동화·다른 앱 연동용)

| 메서드·경로 | 본문 | 동작 |
|---|---|---|
| GET `/status` | | 연결 포트, 이동 중 축, 센서 값, 장부, 기록 |
| GET `/seq` | | 시퀀스 계획(단계별 실제 명령·예상 시간), 진행 상태, 기록 |
| GET `/ports`, `/cameras`, `/cam/<번호>.jpg` | | 포트 목록, 카메라 상태, 카메라 화면 |
| POST `/connect` / `/disconnect` | `{"port": "/dev/cu..."}` 또는 `"mock"` | 보드 연결/해제 |
| POST `/cmd` | `{"c": "F"}` | 한 글자 명령 (수동) |
| POST `/beat` | | 누르는 중 신호 (0.5초 끊기면 서버가 X) |

## 11. 값 바꾸는 법

값은 전부 `config/prealign_sequence.json`에 있습니다. 패널을 다시 켤 필요 없이 **다음 실행부터** 반영됩니다(시퀀스 시작 때 파일을 다시 읽음).

| 바꾸고 싶은 것 | 위치 |
|---|---|
| 단계의 숫자 (예: Z 1100 → 1200) | `steps[*].cmds` 의 숫자 |
| "끝까지" 구동량 | `axes.<축>.full` (Y 리니어 6500ms, X 레일 280000스텝, Y 레일 95000스텝) |
| 원상 복구 시 박스 앞 여유 | `axes.x_rail.box_margin` (스텝, 현재 8,000) |
| 1·9단계 X 이송량 | `steps`의 1·9단계 `cmds` (Q 250,000스텝, W 250,000스텝) |
| 정밀 X 받는 위치 | 9단계 `steps[*].cmds`의 F 3200 |
| 정밀 X·Y 복귀 기준 | 패널의 **현재 정밀 X·Y를 오른쪽 위 기준으로 저장** |
| 단계 추가·삭제·순서 | `steps` 배열 (`no`는 화면 표시·"이 단계만"용 번호) |
| 프리얼라인 회전 | `prealign.mask`, `prealign.wafer`의 카메라·영역과 `prealign.quarter_turn_ms`의 공통 90° 구동 시간(550ms). 방향별 실측은 `out/prealign_d8_timing.json`에 진단용으로 저장 |

명령 글자: 숫자 = 그 값, `"full"` = 축 최대값, `["X_RAIL_TO","box"|"stage"]` = X 레일 절대 위치, `["FINE_STAGE","receive"]` = 오른쪽 위 기준의 정밀 X·Y 수취 위치, `["M",0|1]` = 전자석.

## 12. mm 보정 절차 (다음 사람이 꼭 할 일)

1. 패널을 켜고 해당 축을 끝에서 떨어진 곳에 둔다.
2. 캐리지 옆에 자(또는 버니어)를 대고 시작 위치를 표시.
3. "정확한 이동"에서 예: `W` `20000` → 이동.
4. 이동 거리 d(mm)를 잰다. **스텝/mm = 20000 / d**.
5. 반대 방향으로 같은 스텝 → 처음 위치로 돌아오는지 확인 (탈조·백래시 확인).
6. 축마다 반복 (X 레일, Y 레일, 정밀 X, 정밀 Y). 드라이버마다 DIP가 다를 수 있음.
7. `axes`에 `steps_per_mm`를 넣고, `full`·여유를 mm × 스텝/mm로 다시 계산. 예: 200mm 레일, 양끝 5mm 여유 → 190mm × 스텝/mm.

참고 계산식: 스텝/mm = (200 × 마이크로스텝) ÷ 리드(mm). 예) 리드 8mm, 1/8 마이크로스텝 → 200 스텝/mm.
참고 실측: Y 레일 E 95,000스텝이 박스 끝까지, X 레일 280,000스텝이 FOUP 앞 → 스테이지 끝. 레일 길이와 대조하면 대략 검산 가능.

## 13. 문제 해결 (지금까지 실제로 겪은 것)

| 증상 | 원인 | 해결 |
|---|---|---|
| 전원 켜자마자 서보가 계속 돎 | 연속회전 서보에 원본 펌웨어가 0(=최고속)을 씀 | 현 펌웨어는 부팅 시 90(정지). 그래도 돌면 SMPS 끄고 서보 신호선(D5, D8) 확인 |
| 보드가 아무 응답 없음, 명령도 안 먹음 | ADS1115 무응답 시 `setup()`의 I2C에서 영원히 멈춤 (AVR 코어 1.8.8에 `WIRE_HAS_TIMEOUT` 없음) | 현 펌웨어는 타임아웃을 항상 켬. 부팅되면 `READY` 출력 |
| 보드가 "ALIGNER MEGA READY"라고 함 | 누군가 `aligner_mega`(11/5 배선)를 올림. 글자와 핀이 다름 (O/P=Foyu X 등) | 명령 보내기 전에 펌웨어 확인. `mega_previous`를 다시 업로드 |
| USB 꽂으면 잠깐 잡혔다가 허브째 사라짐 | 허브 3단 연결 + 카메라 3대 전류 부족 | 전원 있는 허브, 아두이노는 Mac에 직접 |
| Mac이 USB 장치를 아예 못 봄 | Apple Silicon "액세서리 연결 허용" 창 | 허용 누르기 |
| 카메라 "did not open / not authorized" | 터미널에 카메라 권한 없음 | 시스템 설정 → 카메라 → 터미널 켜고 터미널 재시작 |
| 카메라 1대 "Camera read failed" | 한 USB 2.0 허브에서 320×240 3대 = 대역폭 초과 | 1대를 Mac 본체 다른 포트에 |
| 레일이 한 방향으로만 감 | DIR 신호가 드라이버에 안 감 (DIR+ 5V 공통 누락·핀 오배선) | DIR 핀(53, 27 등) 전압이 명령마다 0/5V 바뀌는지 멀티미터로 확인 |
| 끝에서 갈리는 소리 | 리밋 없이 정해진 스텝을 보내 끝에서 탈조 | 절대 위치 + 여유 (4장). 근본 해결은 리밋 스위치 |
| 전자석이 안 켜짐 (패널은 ON) | 전자석 구동 회로 빠짐 / D11 배선 | 회로·전원 확인. M은 토글이라 상태가 꼬이면 `#M 1`(절대값) 사용 |
| 웨이퍼를 든 채 패널 재시작 → 웨이퍼 떨어짐 | 시리얼을 열면 Mega가 리셋 → 전자석 OFF | 웨이퍼 내려놓은 뒤 재시작 |
| 시퀀스 단계가 겹쳐 실행됨 (11/20) | 외부 스크립트가 `/seq` 조회 실패를 '완료'로 착각하고 다음 단계를 보냄 | 패널 버튼 또는 `/seq`의 `running`이 false가 될 때까지 기다린 뒤 다음 단계 |
| Z/Y 리니어가 안 움직임 | 이미 그 방향 끝 (DC 액추에이터 내장 리밋) | 반대 방향으로 짧게 보내 확인 |
| Y 리니어 넣은 뒤 살짝 튀어나옴 | 끝 충돌 반동 추정 | 기구 확인 |
| 레이저 값 대신 `ADS_ERROR` | ADS1115 전원·I2C 배선 | 외부 5V, GND 공통, SDA 20/SCL 21 |

| 정밀 X 버튼을 눌렀는데 Y가 움직임 | 대문자 **F/B = 정밀 X**, 소문자 **f/b = 정밀 Y** | 대소문자 확인 |
| 정지 후 원상 복구 위치가 틀림 (11/20 이전) | 중간 정지한 이동이 장부에 안 남음 | 펌웨어가 `STOP <축> <간 양>`을 보내도록 수정 (실장비 확인) |
| 정밀 X 수취 위치 확인 | 9단계 W 이송 완료 후 F 3200 | 9단계 F 명령과 완료 로그 확인 |

## 14. 안전 체크리스트

- [ ] 처음 켤 때 SMPS OFF → USB 연결 → 패널 "연결됨" → SMPS ON
- [ ] 서보 두 개가 멈춰 있는지
- [ ] 장비 주변(레일 경로, FOUP 입구, 스테이지 위) 손·물건 치우기
- [ ] 장부 기준이 맞는지 (`/status`의 ledger, 의심되면 기준(0) 다시)
- [ ] 처음 쓰는 값은 "이 단계만"으로 한 단계씩
- [ ] 정지 = Space / Esc / 빨간 버튼 (서보·전자석은 정지 버튼으로 꺼지지 않음 — 서보는 `T`/`#t`·`#A` 끝, 전자석은 `#M 0`)
- [ ] 끝나면 원상 복구 → SMPS OFF
