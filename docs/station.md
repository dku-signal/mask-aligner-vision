# 통합 스테이션: 프리얼라인 → 정밀 얼라인 연속 운전 (2026-11-24)

`tools/station.py` 하나로 **이송·프리얼라인(8790 패널)과 정밀 얼라인(`mask_aligner_optimized_v4.py`)을 같이** 돌립니다. 정밀 얼라인이 웨이퍼 N을 맞추는 동안 이송 팔은 박스로 돌아가 웨이퍼 N+1을 가져와 각도까지 측정해 두고, 스테이지가 비면 바로 넘겨줍니다.

```
웨이퍼 1: [가져오기 0~8] [넘겨주기 9~14] [정밀 얼라인 ─────────────]
웨이퍼 2:                                [가져오기 0~8] (대기)        [넘겨주기] [정밀 얼라인 ───]
웨이퍼 3:                                                                       [가져오기] (대기) …
```

**알고리즘과 수치는 그대로입니다.** 정밀 얼라인은 `MaskAlignerApp`(검출기, θ→XY, 0.65px FINISH, Z 하강·상승, 세타·XY 복귀)을 그대로 쓰고, 이송은 `config/prealign_sequence.json`의 단계·값(1단계 Q 250,000, 8단계 두 키 측정, 9단계 이송 중 D8 보정 + F 3200 …)을 그대로 씁니다. 바뀐 것은 **두 프로그램을 잇는 배관**입니다.

## 실행

```bash
python tools/station.py                                  # 아두이노 자동, 카메라 0(정밀·마스크) 1(웨이퍼)
python tools/station.py --detector yolo-2pair --frame 1280x720
python tools/station.py --mock                           # 보드 없이 (가상 보드)
```

- 통합 화면: `http://127.0.0.1:8790` — 맨 위 **연속 운전** 카드, 그 안에 정밀 얼라인 화면(8765)이 그대로 들어 있고, 아래는 기존 이송 패널(수동 조작·시퀀스·원상 복구·카메라)입니다.
- 정밀 얼라인 원래 화면도 `http://127.0.0.1:8765`에서 그대로 열립니다.
- **펌웨어 v2가 필요합니다** (`firmware/mega_previous`, 2026-11-24). v1은 레일을 하나씩만 움직여 정밀과 이송이 동시에 돌 수 없습니다.
- `tools/motor_panel.py`, `mask_aligner_optimized_v4.py`를 **따로** 실행하는 방법도 그대로 됩니다(한 번에 하나만 보드를 잡음).

## 연속 운전 사용법

1. SMPS OFF → USB 연결 → `python tools/station.py` → 통합 화면에서 보드 "연결됨", 카메라 0·1 확인 → SMPS ON.
2. 정밀 X·Y를 오른쪽 위에 두고 정밀 화면의 **현재 위치를 오른쪽 위 기준으로 저장** (기존과 같음).
3. 이송 팔이 정밀 스테이지 쪽 끝, Z 맨 아래, 정밀 스테이지가 비어 있는지 확인.
4. **▶ 연속 운전 시작**.
5. 한 장의 정렬이 끝나면 상태가 "작업자: 정렬된 웨이퍼를 치우고 '스테이지 비움 확인'"으로 바뀝니다. 웨이퍼를 치우고 **✔ 스테이지 비움 확인**. 이미 가져와 둔 다음 웨이퍼가 바로 넘어갑니다.
   - 정렬된 웨이퍼를 치우는 장치가 아직 없어서 기본은 확인을 기다립니다. **"확인 없이 자동 진행"**을 켜면 기다리지 않습니다(시연용).
6. 끝나는 조건: **최대 장수**(0 = 무제한)에 도달 / 8단계에서 웨이퍼가 검출되지 않음(박스가 빈 것으로 판단) / **■ 연속 운전 정지** / 빨간 전체 정지 / 정밀 얼라인 실패(FAULT).

상태 줄: 가져옴·넘김·정렬 완료 장수, 이송 팔이 웨이퍼를 들고 있는지, 정밀 스테이지 상태(비어 있음 / 정렬 중 / 정렬 완료 (치워야 함) / 정렬 실패), 정밀 얼라인 단계, 이송 단계.

## 무엇을 바꿨나 (구조)

| 문제 (전) | 해결 (후) |
|---|---|
| 정밀 앱과 이송 패널이 각자 시리얼 포트를 열어 한 번에 하나만 보드를 쓸 수 있었음 | 이송 패널의 `Board` 하나가 포트를 갖고, 정밀 앱은 `BusLink`(ArduinoLink와 같은 모양)로 같은 보드에 명령 |
| 펌웨어가 레일을 하나씩만 구동 — 정밀 X가 움직이면 이송 레일이 멈춤 | 펌웨어 v2: 레일 4개 동시 구동, DC 3쌍·서보 2개 각자 타이머 |
| 정지 `X`가 모든 축을 멈춤 | `#X <글자들>`로 한쪽만 정지. 정밀 STOP = `#X FBfbAud`, 이송 정지 = `#X QWERJHKLOPtM`. 빨간 전체 정지는 여전히 모두 정지 |
| 응답이 한 큐에 섞임 — 두 쪽이 동시에 기다리면 서로의 DONE을 가져갈 수 있음 | 축 글자별 우편함: `DONE/STOP <글자> <값>`은 그 글자를 기다리는 쪽에만 전달 |
| 카메라 0을 정밀 앱과 프리얼라인 측정이 각자 열려고 함 | 정밀 앱이 열고, 8단계 측정은 같은 프레임을 빌려 씀 (`_SharedCapture`) |
| 정밀 스테이지가 움직이면 8단계 측정이 무효가 됨 | 측정을 무효로 만드는 것은 **이송 축**(Q W E R J H K L O P t M) 움직임뿐. 정밀 스테이지는 이송 팔 위 웨이퍼를 건드리지 않음 |
| 연속 처리 없음 | `Pipeline`: 가져오기 → (정밀 종료·비움 확인 대기) → 넘겨주기 → 정밀 START → 다음 가져오기 … |

### 축 나눔

| 쪽 | 글자 | 축 |
|---|---|---|
| 정밀 얼라인 | F B f b A u d | 정밀 X·Y, 정밀 θ 서보(D5), 정밀 Z(마스크 판, Z1) |
| 이송·프리얼라인 | Q W E R J H K L O P t M | 이송 X·Y 레일, Y 리니어, Z 리니어, 프리얼라인 서보(D8), 전자석 |

예외: 9단계의 **F 3200**(정밀 X 수취 위치)은 이송 시퀀스가 보내지만, 정밀 얼라인이 끝나 정밀 스테이지가 쉬고 있을 때만 실행됩니다(연속 운전이 정밀 종료를 기다린 뒤 9단계를 시작).
통합 스테이션에서 정밀 앱 화면의 이송 관련 버튼(이송 실행·로더 등)은 막힙니다 — 이송은 통합 화면의 시퀀스로 합니다.

## 검증 범위 (2026-11-24)

- `pytest -q` 62개 통과 (기존 57 + 통합 5). 기존 테스트 중 의도적으로 바뀐 동작 6곳은 테스트를 고쳐 반영: 정지 명령이 `X` → `#X QWERJHKLOPtM`, 정밀 스테이지 이동은 8단계 측정을 유지(이송 축 이동은 여전히 무효).
- 가상 보드: 3장 연속 운전에서 정렬 중에 다음 웨이퍼 가져오기(Q)가 나가는 것, 비움 확인 전에는 넘기지 않는 것, 정밀·이송 동시 명령의 응답 분리, 정밀만 정지해도 이송 레일이 끝까지 가는 것을 확인.
- 통합 화면·정밀 화면·가상 보드 연결 확인.
- **실장비 미확인:** 펌웨어 v2 업로드와 동시 구동, 실제 카메라로 정밀 START, 한 사이클 전체. 처음에는 최대 장수 1로 돌려 보세요.

## 알아둘 점

- **박스의 슬롯 높이.** 5단계 Z 1100ms는 한 슬롯 높이입니다. 박스(FOUP)에 여러 장이 층마다 꽂혀 있다면 장마다 Z 높이가 달라야 합니다. 슬롯별 높이를 재서 알려 주면 `cmds`를 장수에 따라 바꾸도록 넣겠습니다.
- 8단계 마스크 측정은 정밀 얼라인 중인 카메라 0 영상에서 합니다(정렬 중인 웨이퍼가 같이 보임). 마스크 사각점이 YOLO로 잘 잡히는지 첫 실장비 시험에서 확인하세요.
- 같은 축에 두 쪽이 명령을 보내는 일은 연속 운전 순서상 없지만, 수동 버튼을 누르면 그 축의 진행 중 명령은 `STOP`으로 끝납니다. 연속 운전 중에는 수동 버튼을 쓰지 마세요.
