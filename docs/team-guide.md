# 팀 실행 가이드

[프로젝트 소개로 돌아가기](../README.md)

이 문서는 현재 팀 저장소의 `mask_aligner_optimized_v4.py`와 `firmware/xy_tb6560` 조합을 설명합니다. 별도 `wafer_align` 실험 앱과 프로토콜을 혼용하지 않습니다.

## 1. 설치

Python 3.11 환경의 기본 영상·통신 의존성:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows에서는 `py -3.11 -m venv .venv` 후 `.venv\Scripts\activate`를 사용합니다. 아래 `python`은 이 환경의 Python을 가리킵니다.

AI 검출 경로의 추가 설치와 가중치는 [모델 가이드](model-pipeline.md)를 확인하세요. 기본 `opencv` 경로는 torch와 SAM2가 필요하지 않습니다.

## 2. 현재 하드웨어와 명령

| 축 | 핀 | 명령 예시의 의미 |
|---|---|---|
| X | STEP D10 / DIR D11 | `X <steps>`: 부호가 있는 상대 펄스 수 |
| Y | STEP D8 / DIR D9 | `Y <steps>`: 부호가 있는 상대 펄스 수 |
| θ | 신호 D30 | `T <id> <dir> <duration_ms>`: 방향 ±1, 구동 시간 |

시리얼은 9600 baud, LF 줄바꿈입니다. X/Y 이동 완료 응답은 `DONE`, θ는 `DONE T <id>`입니다. `PING` 응답은 `PONG`, `POS`는 저장된 펄스 위치와 소프트웨어 제한을 반환합니다. `S` 또는 `s`로 정지합니다.

현재 θ 기본 신호는 neutral 1500 μs, 방향별 ±100 μs 오프셋입니다. 펌웨어 T 명령의 시간 범위는 20–250 ms이고, 앱은 현재 장비의 관측을 반영해 최소 60 ms를 사용합니다. 구동 시간을 실제 각도로 해석하려면 응답을 관측해야 합니다.

`PONG`만으로 펌웨어 버전과 모든 핀을 확인한 것은 아닙니다. 보드에 업로드한 소스와 지원 명령을 함께 확인합니다. 기존 F/B 전용 스케치와는 앱 명령 규약이 다릅니다.

## 3. 실행 전 점검

- 액추에이터 고정, X/Y 이동 및 θ 회전 여유, 케이블 간섭을 확인합니다.
- 카메라와 Arduino USB를 연결하고 모터 드라이버 전원을 확인합니다.
- Arduino IDE의 **시리얼 모니터·플로터**와 같은 포트를 사용하는 다른 앱을 닫습니다.
- 마스크 사각형 네 개와 웨이퍼 키가 화면에 들어오게 하고 초점·노출을 확인합니다.

```bash
python preflight.py
```

장치 포트를 직접 지정하려면:

```bash
python preflight.py --port /dev/cu.usbmodemXXXX
# Windows 예: --port COM3
```

preflight는 통신·카메라·기본 키 인식을 점검합니다. YOLO 가중치의 성능이나 기계 이동량을 인증하는 검사는 아닙니다.

## 4. 교정 파일 확인

현재 `calibration.json`은 **2026-10-12** 장비 설정에서 측정한 값입니다.

| 항목 | 파일의 값 |
|---|---:|
| 영상 X | 202.5121 steps/px |
| 영상 Y | 225.5299 steps/px |
| 카메라↔명령 축 교환 | `SWAP_XY_COMMANDS=true` |
| XY 기준 | 축별 0.5 px |
| 앱의 축별 최대 명령 | 13,531 steps |

카메라 배율·해상도·각도, 모터 배선, 마이크로스텝 설정이 달라지면 기존 교정값을 재사용하지 않습니다. steps/px는 μm/px와 다릅니다.

새 교정이 필요할 때만 하드웨어 담당자와 실제 이동 여유를 확인하고 `calibrate_xy.py`를 실행합니다. **이 스크립트는 모터를 움직이며 설정을 바꿉니다.** `--zero`는 현재 위치를 0으로 바꾸므로 단순 통신 확인용으로 쓰지 않습니다. `--limit` 또한 실제 레일 여유를 확인한 값으로 설정합니다.

`POS`의 누적 펄스는 엔코더 실측 위치가 아닙니다. 저장된 제한이나 파일의 `_soft_limit_steps`만으로 현재 기계의 이동 여유가 보장되지 않습니다. `tools/find_limits.py`는 레일 끝까지 구동하는 진단 도구이므로 일반 시작 절차에 넣지 않습니다.

## 5. X/Y/θ 실행

```bash
python mask_aligner_optimized_v4.py --camera auto --detector opencv
```

브라우저에 두 키가 표시되는지 확인하고 **START ALIGN**을 누릅니다. 현재 앱은 θ 보정 → X/Y 보정 순서로 새 영상을 사용해 반복 동작합니다. 모델 경로는 `--detector yolo-sam2`로 선택합니다. [필수 준비](model-pipeline.md)

θ를 제외한 X/Y 시험:

```bash
python mask_aligner_optimized_v4.py --camera auto --detector opencv --skip-theta
```

포트와 카메라를 직접 지정하는 예:

```bash
python mask_aligner_optimized_v4.py   --camera 0 --arduino-port /dev/cu.usbmodemXXXX --port 8767   --detector opencv
```

웹 앱의 `--port`는 HTTP 포트입니다. Arduino 포트는 `--arduino-port`로 지정합니다. 반면 `preflight.py`와 `calibrate_xy.py`의 `--port`는 Arduino 포트를 뜻합니다.

### 노치 프리얼라인과 자동 전달

프리얼라인은 `firmware/aligner_mega/aligner_mega.ino`의 `PX`, `PZERO`, `PY` 명령을 사용합니다. 보드에 올리기 전에 이 스케치의 R1/R2, 프리얼라인 서보, 전자석 핀을 실제 배선과 대조합니다.

1. 웨이퍼 외곽 전체가 보이는 카메라를 `PREALIGN.notch_camera`에 지정합니다. 현재 선택된 정밀 얼라인 카메라를 함께 쓰려면 `null`을 유지합니다. `notch_roi`를 쓰려면 웨이퍼 외곽이 잘리지 않는 `[x, y, 너비, 높이]`를 픽셀로 지정합니다.
2. 원하는 노치 방향을 `target_notch_deg`에 입력합니다. 화면 오른쪽이 0°이고 아래쪽이 +90°입니다. `theta_ms_per_degree`는 프리얼라인 서보의 구동 시간(ms)/영상 회전각(°)입니다. 양의 펄스 명령으로 영상에서 반시계 방향으로 회전하면 음수를 사용합니다.
3. 이송 시작 위치에서 **X 오른쪽 끝 전달 위치**까지의 부호 있는 R1 스텝 수를 `x_steps`에 입력합니다. `y_max_steps`에는 R2 기준점에서 **완전 전진 전달 위치**까지의 부호 있는 스텝 수를 입력합니다.
4. Y 이동 뒤 필요한 전진, Z 하강, 전자석 해제, 이송부 후퇴를 `handoff`에 순서대로 설정합니다. 지원 명령은 `MAG`, `R1`, `R2`, `FY`와 시간 지정 `Z <축 번호> <방향> <ms>`입니다. 장비에서 확인한 채널과 시간을 사용합니다.
5. 앱을 다시 실행합니다. 웨이퍼를 이송부에 미리 장착하고, 이송부를 교정에 사용할 정지 위치에 둔 뒤 **현재 이송 X·Y 위치를 기준점으로 등록**을 누릅니다. 중단 후에는 두 축을 등록한 시작 위치로 돌려놓은 뒤 재실행합니다. Arduino가 리셋되면 기준점을 다시 등록합니다.

앱은 정지 영상 3장에서 노치 각도를 확인합니다. R1이 설정된 이동거리의 절반에 도달하면 Arduino가 R1 펄스를 계속 내면서 연속회전 θ 서보를 시간과 방향으로 제어합니다. 이송 중에는 Z 높이를 고정합니다. R1 이동을 마치면 R2를 최대 전달 위치까지 전진시키고 `handoff`를 실행합니다. 새 정밀 카메라 영상이 들어오면 키 기반 정밀 얼라인을 시작합니다.

#### 방법 2 · 정밀 얼라인의 X 스텝 반영

- `precision_x_axis`에 이송 X와 나란히 움직이는 정밀 Arduino 모터의 명령 축(`X` 또는 `Y`)을 설정합니다. `precision_to_transfer_x_ratio`에는 **정밀 모터 1스텝에 해당하는 R1 스텝 수**를 부호까지 포함해 적습니다. 두 모터의 양의 명령이 같은 방향이면 양수, 반대 방향이면 음수입니다.
- 첫 시험은 **오른쪽 끝에서 X 교정**을 누릅니다. 앱은 X 최대 스텝으로 전달하고, 정밀 얼라인이 완료되면 해당 모터가 완료 응답을 보낸 양·음의 이동 스텝을 합산해 `out/rig_config.prealign-x.json`에 저장합니다. 스텝 환산비를 비워 둔 상태에서도 측정 스텝은 저장됩니다.
- 다음 웨이퍼는 같은 기준점에서 **프리얼라인 → 정밀 얼라인**으로 시작합니다. 첫 교정에서 X가 왼쪽으로 보정됐다면 최대 스텝 수에서 환산한 왼쪽 보정량만큼 덜 이동합니다. 이후에는 직전 X 이송 목표에 새로 관측한 잔여 보정량을 반영합니다. Y는 설정한 최대 전달 위치로 이동합니다.
- 보정 결과가 등록된 X 이동 범위를 벗어나면 자동 이송이 시작되지 않습니다. 기준점과 스텝 환산비를 확인합니다. 중단하거나 실패한 정밀 얼라인은 저장된 교정값을 갱신하지 않습니다. 배치 기준을 다시 잡을 때는 **오른쪽 끝에서 X 교정**을 사용합니다.

## 6. 결과 읽기와 종료

- `dx`, `dy`: 영상 좌표에서 웨이퍼 중심 − 마스크 중심, 단위 px.
- `theta_error`: 현재 영상에서 얻은 상대 각도. 관측할 수 없으면 null일 수 있습니다.
- `theta_done_error`: θ 단계를 마칠 때 저장한 각도. 전체 정렬 종료의 최신 각도와 다를 수 있습니다.
- `DONE`: 현재 앱의 완료 조건을 만족했다는 상태. 최종 μm 정밀도나 패턴 전체 겹침의 보증은 아닙니다.

현재 θ 단계 기준은 4°이고 두 번 확인하면 XY로 넘어갑니다. XY 단계는 새 영상의 중심 정렬 확인을 8회 모아 완료합니다. 화면의 일부 설명 문구보다 현재 코드·교정 파일과 결과 로그를 기준으로 확인합니다.

종료할 때 **STOP**으로 이동 중단을 확인하고 터미널에서 `Ctrl+C`로 앱을 종료합니다. 작업을 마치면 모터 SMPS 전원을 끕니다. STOP은 전원 차단이 아니며, USB 분리만으로 드라이버 전원이 차단되는 것도 아닙니다.

## 7. 펌웨어 설치가 필요한 경우

이미 호환 펌웨어가 올라가 있다면 매번 업로드하지 않습니다. 2026-10-12 재시험에서는 현재 보드의 명령 지원을 확인하고 **업로드 없이** 실행했습니다.

변경이 필요하면 Arduino IDE에서 `firmware/xy_tb6560/xy_tb6560.ino`, 보드 **Arduino Mega 2560**, 실제 포트를 선택합니다. macOS용 `tools/flash.sh`는 백업·업로드 도구입니다. 리셋 중 예기치 않은 구동을 피하려면 모터 SMPS 전원을 끄고 Arduino USB만 연결해 업로드하는 절차를 사용합니다. 업로드 후 시리얼 모니터를 닫고 앱을 실행합니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 포트 열기 실패 / PONG 없음 | 시리얼 모니터·다른 앱의 포트 점유, 포트 이름, 펌웨어 명령 지원 |
| DONE 응답은 오지만 이동 없음 | SMPS·드라이버·기구 상태와 영상상 변위를 함께 확인. 응답만으로 이동 성공 판단 금지 |
| 큰 소리·진동만 남 | 구동을 중단하고 전원·배선·드라이버·가감속·기구 구속을 확인 |
| 키 인식 실패 / MASK 3개 | 화면 잘림, 가림, 초점, 조명, 대상 키 형상 |
| ERR X/Y limit | 현재 위치·제한과 실제 레일 여유를 확인. 제한을 임의로 키우지 않음 |
| θ 완료인데 마지막 각도가 이상함 | 저장된 종료 각도와 현재 각도를 구분하고 최종 사진에서 재측정 |
| YOLO/SAM2 실행 실패 | 추가 패키지, 키 전용 best.pt 경로와 클래스, 모델 다운로드 접근 확인 |

## 팀 개발 흐름

기능 변경은 브랜치에서 작업하고 PR에 문제·변경 내용·검증 범위를 적습니다. 실물 구동, 관찰 전용 인식, 합성 테스트 결과를 구분합니다. 가상환경, 가중치, 데이터셋, 펌웨어 덤프와 무검토 카메라 원본은 커밋하지 않습니다.
